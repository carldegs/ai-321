1. Learn a dynamic map from a physical experiment

The two-tank experiment separates the physical system from the model used to approximate it. Pump voltage is the input; the lower tank's liquid level is the measured output. In the diagram, pump flow enters the upper vessel, its drain feeds the lower vessel, and the lower drain leaves the system. Both tanks store water, so a change in voltage produces a gradual level response rather than an instantaneous proportional output. A nonlinear black-box model learns this temporal map from observations without estimating all physical constants. Grey-box identification instead starts with chosen physical equations and estimates their unknown coefficients.Source evidence: Figure 17, Data and split code.

The scripts describe 3000 samples taken every \(T_s=0.2\) seconds. Here \(T_s\) is the sampling interval, so the nominal record duration is \(3000T_s=600\) seconds and the sampling rate is \(f_s=1/T_s=5\) Hz. These duration statements describe sample coverage; the difference between the first and last timestamp is one sampling interval shorter. In the saved input-output plots the horizontal axis is time in seconds. The upper panel is output amplitude, interpreted from the source description as lower-tank level in metres; the lower panel is pump input in volts. Piecewise constant input changes excite the system, while rounded rises, decays, and delayed peaks in the output reveal memory and operating-point dependence.Source evidence: Figure 1, Figure 6, Figure 11, Data and split code.

The tree and custom-feature examples divide the record into consecutive 1500-sample blocks, whereas the archived tutorial uses three consecutive 1000-sample blocks. The tutorial explicitly treats its second block as more similar to the estimation regime and its third as a harder extrapolation case. A chronological split tests later behavior without randomly interleaving adjacent samples; it does not, by itself, prove independence or eliminate every source of leakage. The plots justify comparing transient shapes and operating ranges, but neither their colors nor a high fit percentage establish that the input excites every mode needed for identification.Source evidence: Figure 1, Figure 6, Figure 11, Data and split code.

Tutorial walkthrough. Mark each pump step, then follow the upper level trace. Estimate whether the output begins changing immediately, where its slope changes, and whether the same input amplitude produces the same transient at different initial levels. These observations motivate delays, memory length, and nonlinear features without assuming a fitted model is already correct.
Testable distinction. A nonlinear output map is different from a time-varying model. A fixed learned function can respond differently at different water levels while using the same parameters at every date. No dataset or MATLAB model was executed to create this guide; all plotted results are preserved outputs from the supplied live scripts.

2. Preprocessing changes both the signal and the question

The tree-ensemble workflow splits the observations before filtering, then applies the same low-pass specification separately to both blocks. Its code uses idfilt(z1,3,0.066902) and an equivalent call for validation, followed by 20:end. The saved estimation and validation plots overlay raw and filtered traces. On the upper panels, rapid fluctuations around the level trajectory are suppressed; on the lower panels, the sharp pump steps acquire smoothed transitions. Filtering therefore affects both observed inputs and outputs, and the filtered dynamic relation is the immediate object being fitted.Source evidence: Figure 2, Figure 3, Filtering code.

Indexing from 20 retains 1481 observations out of each 1500-sample block; it removes 19 samples, not 20. At \(T_s=0.2\) seconds this drops 3.8 seconds of initial samples from each block. These counts follow directly from inclusive MATLAB indexing. The guide does not reinterpret the literal cutoff argument as hertz without checking the installed function's convention. The custom-regressor script describes preprocessing in its narrative, but its displayed estimation calls use the raw split data_est=z1; it does not reproduce the tree example's filtering-and-trimming steps. Differences in fit across these workflows must therefore be interpreted with their different targets in mind.Source evidence: Figure 2, Figure 3, Filtering code, Custom-regressor code.

As a tutorial principle, preprocessing should be specified using estimation data and deployment requirements. A filter can introduce delay, endpoint transients, or access to future samples depending on its implementation. Validation preprocessing must respect the intended prediction setting; splitting first avoids one obvious cross-boundary mixing mechanism but does not automatically make a transformation causal. If a model will predict raw sensor level online, performance on a separately filtered target is insufficient evidence. Preserve the raw validation record as well as the transformed version and state which one each comparison evaluates.Source evidence: Figure 2, Figure 3, Filtering code.

Tutorial walkthrough. Record the original indices, apply the declared transformation, then record the retained indices again. Confirm that input and output timestamps still align. Compare both filtered-target and raw-target residuals if both are meaningful deployment tasks. Interpret a cleaner trace as a changed representation, rather than proof that every discarded fluctuation was irrelevant.
Common pitfall. Do not infer cutoff units, filter phase, or online availability from the number 0.066902 alone. A model validated on filtered data and one validated on raw data do not share the same denominator or target signal. Their headline percentages are not directly interchangeable.

3. Put the right memory and physics into the regressors

A nonlinear ARX model separates temporal feature construction from static function approximation. One useful tutorial form is \[\widehat y_t=F_\vartheta(\mathbf r_t),\qquad \mathbf r_t=[y_{t-1},\ldots,y_{t-n_a},u_{t-n_k},\ldots,u_{t-n_k-n_b+1}]^{\mathsf T}.\] Here \(y_t\) is output, \(u_t\) input, \(t\) an integer sample index, \(n_a\) the number of output lags, \(n_b\) the number of input terms, \(n_k\) the first input delay, \(\mathbf r_t\) the regressor vector, and \(F_\vartheta\) a static map with parameters \(\vartheta\). This equation explains the scripts' order convention; a zero input delay includes the current input and is meaningful only when that value is available for the task.Source evidence: Custom-regressor code, Model-structure code.

The custom-feature script constructs output lags 1 and 2 and input lags 0, 1, and 2, then estimates NL1 with idLinear. Adding sqrt(y(t-1)) creates NL2, still using a linear coefficient map over its expanded features. Thus the new model is linear in its fitted coefficients but nonlinear in the original measured level. The source comment that an offset itself makes a system nonlinear needs precision: a nonzero offset makes an otherwise linear input-output map affine, while the square-root feature supplies an actual nonlinear dependence. A square-root flow feature is physically motivated by orifice behavior, but the measured lower level alone is not a complete derivation of the two-tank state dynamics.Source evidence: Custom-regressor code, Figure 7, Figure 9.

The raw-data comparison shows NL1 missing the low-level behavior and producing a negative simulated level in validation. The saved NL1 fits are 76.61% on estimation and 73.24% on validation. NL2's saved fits rise to 84.56% and 86.11%, respectively; its validation response follows the near-zero plateau better but visibly overshoots the high-level transient. On these graphs, horizontal position is time in seconds, and vertical position is the lower level amplitude. Better agreement demonstrates a useful feature on these saved splits, not guaranteed physical constraints. Evaluating a square root recursively also requires a defined policy if a simulated or noisy level becomes negative.Source evidence: Figure 7, Figure 8, Figure 9, Figure 10, Custom-regressor code.

Tutorial walkthrough. Compare [2 3 0] with the explicit lag set: two previous outputs plus current and two previous inputs gives five base features. Adding one square-root feature gives six. Keep this distinction separate from the nonlinear model's number of fitted parameters or hidden units.
High-yield edge case. A model can be linear in coefficients and nonlinear in observations. Feature engineering does not ensure nonnegative simulated output or stable rollout. Negative water levels should trigger a modeling and domain check rather than an unexamined square-root operation.

4. Choose a nonlinear architecture that matches the structure

The tree example uses idTreeEnsemble with two very different memories: [30 30 0] includes past outputs and inputs, while [0 150 0] uses input history alone. Thirty output lags reach six seconds into the past; 150 input terms with zero first delay span lags 0 through 149, reaching 29.8 seconds back at the stated sample rate. A regression-tree ensemble partitions feature space and combines leaf predictions; its dynamic behavior arises from the lagged features and, when present, recursive output feedback. The input-only architecture has no output feedback in its regressor definition, but it still carries memory through its input window.Source evidence: Model-structure code, Figure 4, Figure 5.

The archived tutorial compares wavelet mappings, sigmoid mappings, Gaussian-process and tree examples, and a feedforward network used as a static regressor-to-output map. The saved response surface varies two selected regressors while fixing the others: its horizontal coordinates are regressor values and its vertical coordinate is the nonlinear contribution to output. That surface is a slice of the static mapping, not a time trajectory and not a stability certificate. The saved training interface reports stopping at 50 epochs. Reaching an epoch budget says how optimization terminated; it does not establish convergence, appropriate architecture, or generalization. Some tutorial plots are cropped in the supplied saved outputs, and two figure entries contain no saved PNG at all.Source evidence: Figure 12, Figure 13, Figure 15, Figure 16, Model-structure code.

Hammerstein-Wiener models express a different structural assumption. A tutorial representation is \[v_t=f(u_t),\qquad w_t=G(B)v_t,\qquad \widehat y_t=g(w_t).\] Here \(f\) is a static input nonlinearity, \(G(B)\) a linear dynamic filter in backward-shift operator \(B\), \(g\) a static output nonlinearity, and \(v_t,w_t\) internal signals. The archived script explores dead zones, saturation, and piecewise-linear mappings, then compares refinement iterations. This cascade places nonlinearities around a linear memory block; nonlinear ARX instead applies a static map to lagged signals. Neither model family automatically dominates the other, and more optimization on estimation data is not a substitute for an independent validation record.Source evidence: Model-structure code.

Tutorial example. A pump with a dead zone, linear storage dynamics over a limited operating range, and a saturating sensor suggests a Hammerstein-Wiener structure. A regressor-dependent transition whose shape changes jointly with several past levels suggests a more flexible nonlinear ARX map. Use physical plausibility and held-out rollout behavior to decide whether that additional flexibility is justified.
Do not confuse the roles. A feedforward network inside a nonlinear ARX model is static, while the overall model is dynamic because its inputs include lags. The evaporator script uses a NARX feedback network, a different interface and structure. The saved surface and training UI should not be treated as independent validation graphs.

5. Validate the task, the residuals, and the score definition

One-step prediction and free-run simulation test different mechanisms. With measured output history supplied at every step, a predictor may correct itself continually. In free-run simulation, predicted outputs replace unobserved future outputs in recursive features, so small local errors can accumulate. The saved MATLAB figures are titled Simulated Response Comparison and the source calls compare; they should not be silently relabeled as a one-step forecasting benchmark. Initialization and comparison options also affect results. The first tree comparison evaluates estimation data even though its generic measured-data legend says Validation data; the code and its approximately 0–300-second time window resolve that ambiguity.Source evidence: Figure 4, Figure 5, Validation code.

On the saved tree plots, the input/output-memory model reports 90.35% and the input-only model 98.53% on estimation, but 87.73% and 89.75% on validation. The gap shows why a strong training overlay is insufficient. The nonlinear ARX archived tutorial also evaluates two different validation regimes and examines residuals. A tutorial diagnostic is \[e_t=y_t-\widehat y_{t\mid t-1},\qquad \widehat\gamma_e(k)=\frac1N\sum_{t=k+1}^{N}(e_t-\bar e)(e_{t-k}-\bar e).\] Here \(e_t\) is the one-step residual, \(\widehat y_{t\mid t-1}\) the prediction from past information, \(N\) the residual count, \(k\ge0\) a lag, and \(\bar e\) the sample mean. Nonzero lag dependence suggests predictable structure remains; residual-input dependence can reveal missing input dynamics under suitable exogeneity assumptions. A confidence band crossing is evidence to assess, not automatic proof of model failure.Source evidence: Figure 4, Figure 5, Figure 14, Validation code.

The evaporator code explicitly computes 100*(1-goodnessOfFit(...,'NMSE')). For nonconstant reference data, this is the complement of a squared normalized error: \[R_j^2=1-\frac{\sum_t(y_{t,j}-\widehat y_{t,j})^2}{\sum_t(y_{t,j}-\bar y_j)^2}.\] Here \(j\) identifies an output channel, \(y_{t,j}\) is reference output, \(\widehat y_{t,j}\) its aligned prediction, and \(\bar y_j\) the reference mean. This differs from the norm-based percentage used by compare, which takes a square root before the complement. For example, NMSE 0.04 gives 96% by the script's definition and 80% by the norm-based definition. This distinction follows the official goodnessOfFit definitions; percentages from the two definitions must not be compared as identical quantities.Source evidence: Evaporator NARX script, Validation code.

Tutorial walkthrough. Freeze the preprocessing and candidate models, declare prediction horizon and initial-state treatment, then compare them on the same chronological validation samples. Inspect the level trace, transient errors, residual autocorrelation, and input-residual relationship. Report the exact fit formula and per-channel values before calculating an average.
Metric edge cases. The normalized denominator vanishes for a constant reference channel. Scores may be negative when a model is worse than the reference-mean baseline. An average across channels hides which variable fails. None of the saved percentages establishes future extrapolation performance outside the tested regime.

6. Trace the multivariate NARX script before trusting its result

The evaporator file selects columns 1–3 of train as inputs and columns 4–6 as outputs, then applies the same grouping to valid. It declares input delays 1 and 2, feedback delays 1 and 2, and twelve hidden neurons. With three channels in each group, the nominal delayed feature count is \(3\times2+3\times2=12\), where the first term counts input history and the second output history. These are delayed signal coordinates, not twelve independently estimated physical states. The later labels L2, P2, and X2 name the three reported output channels, but the file does not supply their units or the missing dataset's numerical values.Source evidence: Evaporator NARX script.

The script closes the NARX loop before preparing the training sequences, configures 70/20/10 division ratios, and invokes Bayesian-regularized training. Those literal settings should be reported as code intent, not as observed effective dataset partitions: the network's division function and training algorithm determine how the ratios are used. In particular, temporal split behavior must be inspected rather than inferred from ratio values. Validation preparation returns initial conditions and a shortened output sequence; the code aligns predictions with the tail of the validation matrix. The alignment formula is sensible only if the sequence preparation discarded exactly the initial contiguous samples assumed by that tail selection.Source evidence: Evaporator NARX script.

The final three subplots compare measured and modeled channels against sample number, not seconds: no sample interval is specified in this file. Black curves denote actual data and blue curves predicted data in the plotting commands. There are no saved evaporator plots or numerical scores in the supplied folder, so this guide explains the planned evaluation without inventing an observed fit. The external reading list points to LSTM identification, neural state-space models, forecasting, and model conversion. These are follow-up resources rather than evidence that those architectures were trained here. The supplied MATLAB source and archived source text are linked below so every implementation claim can be checked directly.Source evidence: Evaporator NARX script, Folder reading links.

Tutorial trace. Follow the dimensions from matrix columns to cell sequences, lag coordinates, network outputs, and aligned reference rows. Verify the actual time partition and simulation mode in MATLAB before interpreting a plotted fit. Keep the separate validation record independent of model and preprocessing choices.
Evidence boundary. The required datasets file is not supplied in this notes folder. This guide neither executes the script nor claims its training call is compatible with every MATLAB release. Reading a script supports an explanation of its intended workflow, not a reproducibility or performance claim.

Check Your Understanding

Combine the architecture, preprocessing, and validation arguments before opening an answer.

Why can the input-only tree model still represent a dynamic system?

Its 150 input coordinates span a finite history, so the prediction depends on past excitation even without measured-output regressors. At a 0.2-second interval and zero initial lag, this reaches 29.8 seconds into the past. It can approximate the driven response over the represented history, but hidden initial states and disturbances not determined by that history remain limitations. Compare its later validation trace under the same preprocessing rather than judging it solely by its 98.53% estimation score.

Why is the square-root model nonlinear even though its output function is idLinear?

The fitted map is a linear combination of chosen coordinates, but one coordinate is a nonlinear function of observed level. Linearity in parameters does not imply linearity in the original signal. A fixed bias is affine; the square-root coordinate creates nonlinearity. During free rollout, negative predicted levels can also make the next feature undefined in a real-valued formulation, so output-domain handling and physical constraints deserve separate validation.

How can two correct implementations report 96% and 80% on the same predictions?

For normalized squared error 0.04, the complement of NMSE is 0.96, while the complement of NRMSE is \(1-\sqrt{0.04}=0.80\). The evaporator code uses the first definition and MATLAB compare uses the second. Both must use the same aligned reference samples, and neither normalization is meaningful when the reference channel has zero centered variation. A fit percentage without a formula is ambiguous.

Why might a good one-step predictor drift in simulation?

One-step prediction receives measured past outputs, while simulation feeds predicted outputs back into future features. Local error then changes the future regressor vector and can grow through the model's recurrence. Filtering, state initialization, and whether current inputs are available also affect the task. Test free rollout on a frozen chronological validation record and inspect both residual dependence and physical trajectories.

Does the filtering workflow establish that the model will work online on raw data?

No. Splitting before filtering prevents directly filtering across the train-validation boundary, but the filter implementation may still use future samples within a block or introduce latency. The model is fitted and compared against a transformed target. Online raw-output deployment needs a causally available preprocessing plan, alignment checks, and validation against the relevant raw target. Trimming 20:end removes 19 samples and does not alone establish that all initialization effects are gone.

Complete evaporator source

Open extracted source text

load datasets;
 
%% Convert data sets into cell arrays for NARX
% Let X1 = inputs (u) and T1 = outputs (y) of Training Set
X1 = tonndata(train(:,1:3),false,false);
T1 = tonndata(train(:,4:6),false,false);
 
% Let X2 = inputs (u) and T2 = outputs (y) of Training Set
X2 = tonndata(valid(:,1:3),false,false);
T2 = tonndata(valid(:,4:6),false,false);
 
%% Train a NARX using [X1,T1] (Training)
inputDelays = 1:2;                          % No. of lags in u
feedbackDelays = 1:2;                       % No. of lags in y
hiddenLayerSize = 12;                       % No. of hidden neurons
 
net = closeloop(narxnet(inputDelays,...
    feedbackDelays,hiddenLayerSize));       % Set architecture
 
% You can change how the data set is divided:
net.divideParam.trainRatio = 70/100;        % Training Data Size
net.divideParam.valRatio = 20/100;          % Validation Data Size
net.divideParam.testRatio = 10/100;         % Test Data Size
 
[x,xi,ai,t] = preparets(net,X1,{},T1);
net = trainbr(net,x,t,xi,ai);               % Set training algorithm
 
%% Test the NARX using [X2,T2] (Validation)
[x,xi,ai] = preparets(net,X2,{},T2);
Y = cell2mat(net(x,xi,ai))';
M = length(Y); L = length(valid);
fit = (1-goodnessOfFit(Y,valid((L-M+1):L,4:6),'NMSE'))*100;

%% Plot the results (NARX vs. Actual)
subplot(311);
plot(1:L,valid(:,4),'k'); hold on;
plot((L-M+1):L,Y(:,1),'b'); hold off;
 
subplot(312);
plot(1:L,valid(:,5),'k'); hold on;
plot((L-M+1):L,Y(:,2),'b'); hold off;
 
subplot(313);
plot(1:L,valid(:,6),'k'); hold on;
plot((L-M+1):L,Y(:,3),'b'); hold off;
legend('Actual Data','Predicted Data');
 
ylab = {'L2','P2','X2'};
for j = 1:length(fit)
    fprintf('Fit %s:\tR^2 = %.4f%%\n',ylab{j},fit(j));
end
fprintf('Average fit: R^2 = %.4f%%\n',mean(fit));
